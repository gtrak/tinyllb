# Extraction: Metrics Families

Concept: `c_metrics_families` — Prometheus metric collectors grouped into families (backend, queue, throughput) within a shared `Metrics` struct and `Registry`.

---

## Responsibilities

- Expose a single `Arc<Metrics>` handle (`create_metrics()`, `src/metrics/mod.rs:250-252`) carrying all metric collectors for cross-task sharing.
- Register exactly one `prometheus::Registry` instance containing all collectors (`Metrics::new()`, `src/metrics/mod.rs:69-247`).
- Organize collectors into three families: backend, queue, throughput (each documented in a dedicated submodule: `src/metrics/backend.rs:1-9`, `src/metrics/queue.rs:1-11`, `src/metrics/throughput.rs:1-8`).

---

## Interface Surfaces

### Metric Family: Backend (`src/metrics/backend.rs`)

#### `vllm_requests_active` (Gauge)
- **Help text**: "Number of in-flight requests to the vLLM backend" (`src/metrics/mod.rs:107-109`)
- **Labels**: none
- **Input/semantics**: incremented before forwarding a request to the backend; decremented on completion (success or error) (`src/metrics/backend.rs:5-7`)
- **Output**: current count of in-flight backend requests

#### `vllm_errors_total` (IntCounter)
- **Help text**: "Total number of backend errors (5xx responses and network errors)" (`src/metrics/mod.rs:113-115`)
- **Labels**: none
- **Input/semantics**: incremented on 5xx backend responses and network errors; 4xx client errors are NOT counted (`src/metrics/backend.rs:8-9`)
- **Output**: monotonically increasing count of backend errors

### Metric Family: Queue (`src/metrics/queue.rs`)

#### `llm_queue_depth` (GaugeVec)
- **Help text**: "Current number of requests waiting in the queue" (`src/metrics/mod.rs:74-76`)
- **Labels**: `flow_id` (`src/metrics/mod.rs:77`); ephemeral flows aggregate to label value `"ephemeral"` (`src/metrics/mod.rs:22`)
- **Input/semantics**: set by `FifoScheduler`: +1 when a request enters `admit()`, -1 when its semaphore permit is acquired (`src/metrics/queue.rs:5-6`)
- **Output**: per-flow count of queued requests

#### `llm_queue_wait_seconds` (Histogram)
- **Help text**: "Time a request spends waiting in the queue" (`src/metrics/mod.rs:84-86`)
- **Labels**: none
- **Buckets**: `[0.01, 0.05, 0.1, 0.5, 1.0, 2.0, 5.0, 10.0, 30.0]` (`src/metrics/mod.rs:86`)
- **Input/semantics**: observed by `FifoScheduler` when a permit is acquired; measures wall-clock duration from queue entry to permit acquisition (`src/metrics/queue.rs:7-8`)
- **Output**: histogram of per-request wait durations in seconds

#### `llm_active_flows` (Gauge)
- **Help text**: "Number of currently active flows" (`src/metrics/mod.rs:91-92`)
- **Labels**: none
- **Input/semantics**: incremented when a `QueueTicket` is created (permit acquired); decremented when the ticket is dropped on success, error, or panic (`src/metrics/queue.rs:9-11`)
- **Output**: current count of active flows

### Metric Family: Throughput (`src/metrics/throughput.rs`)

#### `llm_tokens_generated_total` (Counter)
- **Help text**: "Total number of tokens generated by the backend" (`src/metrics/mod.rs:95-97`)
- **Labels**: none
- **Input/semantics**: incremented by the proxy after parsing backend responses (`src/metrics/throughput.rs:5-6`)
- **Output**: monotonically increasing count of generated tokens

#### `llm_tokens_per_second` (Gauge)
- **Help text**: "Approximate tokens generated per second (updated every second)" (`src/metrics/mod.rs:101-103`)
- **Labels**: none
- **Input/semantics**: updated every second by a background task that computes rate from `tokens_generated_total` (`src/metrics/throughput.rs:7-8`)
- **Output**: approximate instantaneous token throughput

## Invariants

1. **Single registry per Metrics instance.** All collectors are registered in the single `Registry` created at `Metrics::new()` (`src/metrics/mod.rs:70`). No external code adds collectors post-construction.

2. **`vllm_requests_active` is non-negative.** Gauge is incremented before forwarding and decremented on completion (`src/metrics/backend.rs:5-7`); value is the difference of two monotonic operations.

3. **`vllm_errors_total` excludes 4xx responses.** Only 5xx and network errors are counted (`src/metrics/backend.rs:8-9`); 4xx client errors are explicitly excluded.

4. **`llm_queue_depth` reflects `admit()`/permit-acquire balance.** Value equals requests admitted minus permits acquired (`src/metrics/queue.rs:5-6`).

5. **`llm_active_flows` is bounded by semaphore capacity.** Gauge tracks `QueueTicket` lifetime (create on permit acquire, drop on release/error/panic) (`src/metrics/queue.rs:9-11`); cannot exceed semaphore permit count.

6. **`llm_tokens_per_second` approximates from `tokens_generated_total`.** Gauge is derived from the counter by a background task at 1-second intervals (`src/metrics/throughput.rs:7-8`).

---

## Failure Modes

1. **Registration failure at construction.** `Metrics::new()` panics if any `register()` or collector creation call fails (all use `.expect()` — `src/metrics/mod.rs:79,88,92,98,104,110,116,125,134,143,149,158,164,170,179,183-226`). A duplicate registration name or malformed opts causes immediate process abort.

2. **Gauge underflow.** If decrement logic fires without a matching increment (e.g., double-completion of a request), `vllm_requests_active` or `llm_active_flows` can go negative. Prometheus `Gauge` permits negative values; the metric silently becomes incorrect.

3. **Histogram out-of-range.** `llm_queue_wait_seconds` has a max bucket of 30 seconds (`src/metrics/mod.rs:86`). Waits exceeding 30 seconds are recorded in the `+Inf` bucket but lose granularity.

4. **Rate computation staleness.** `llm_tokens_per_second` is updated at 1-second intervals (`src/metrics/throughput.rs:7-8`). If the background task is blocked, paused, or dropped, the gauge becomes stale and serves a stale value.

5. **Counter overflow.** `vllm_errors_total` and `llm_tokens_generated_total` are unbounded counters. At sustained high rates, `f64` counter precision loss occurs above ~9,007,199,254,740,992.

6. **Label cardinality explosion.** `llm_queue_depth` is labeled by `flow_id` (`src/metrics/mod.rs:77`). If ephemeral flows are not properly aggregated to `"ephemeral"`, unbounded label cardinality increases memory consumption.
